~   2.1 A home já é o diário — falta terminar o corte
    layouts/home.html pagina site.GetPage "/blog" na raiz. Funciona.
    O que ficou estranho:

    a) /blog continua existindo como listagem quase idêntica.
       Título da aba: "Diário de um Computador – Diário de um Computador".
       Duas paginações: /page/2/ e /blog/page/2/.
       Dois RSS conceituais para a mesma fila.

       Escolher uma:
         A) /blog redireciona para /  (aliases em content/blog/_index.md
            não redirecionam a seção; usar um layout que dê
            http 301, ou um netlify/pages trick — no GitHub Pages
            o jeito Hugo é aliases no DESTINO, não na origem).
            Mais simples: deixar /blog no ar, mas com título
            "Arquivo" e um lead de uma linha + link para /.
         B) Tirar a paginação de /blog (pagerSize enorme) para não
            competir com a home.

    b) Canonical da página 2 da home aponta para /  (não para
       /page/2/). Google pode tratar page 2 como duplicata da home.
       Conferir rel=canonical e rel=prev/next no pager do Hextra.

    c) pagerSize: 10 com 12 posts deixa a página 2 com 2 crônicas.
       Ou sobe para 12 (uma página só, por enquanto) ou desce para
       6 (duas páginas densas). 10 é o pior dos dois.

    d) layouts/home.html tem um <br> vazio e breadcrumb desligado
       à toa. Tem também duas colunas fantasmas de 16rem (sidebar
       placeholder + div direita hx:w-64) que estreitam o texto
       no desktop. A home de um diário não precisa do gutter de
       docs do Hextra. disableSidebar já está true; dá para não
       reservar a coluna.

    e) O H1 "Diário de um Computador" + o título da navbar repetem
       o mesmo nome duas vezes acima da dobra. Uma das duas basta.
       Na home, um lead curto (o que já está no _index.md) e ir
       direto para as crônicas.

6. Infra, CI e repositório
================================================================

    6.1 Workflow .github/workflows/hugo.yml
    Ainda:

    - Pin de actions com SHA, ou no mínimo major recente
      (checkout@v4, configure-pages@v5, deploy-pages@v5).
    - Instalar Go. Hugo modules baixam o Hextra; sem Go a
      build quebra em runner limpo em alguns cenários.
        uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
    - Dart Sass via `sudo snap install dart-sass` é lento e,
      neste projeto, inútil (não há SCSS próprio). Tirar.
    - Cache do módulo Hugo além de HUGO_CACHEDIR.
    - Job de preview em pull_request (hugo --minify, sem deploy).
    - --baseURL "${{ steps.pages.outputs.base_url }}/" está certo.
      Não hardcodar a URL no CI.
    - hugo --minify --cleanDestinationDir no CI, para não
      publicar pastas-fantasma de URLs antigas.

    6.2 .gitignore
    Tem um `*.txt` largo demais (esconde este arquivo).
    Completar o que falta e apertar o que sobra:

      /public/
      /resources/_gen/
      .hugo_build.lock
      lista.txt
      *.swp
      .DS_Store
      /node_modules/

    Não ignorar mudancas-sugeridas.txt se quiser versionar a
    pauta de mudanças. Se não quiser, um data/pauta.yaml
    versionado é melhor que um .txt solto.

    6.3 LICENSE
    O README admite que não há licença. Dual, comum em blogs:

      - MIT            para layouts, config, CSS, workflow
      - CC BY-SA 4.0   para o Markdown em content/

    LICENSE na raiz + um parágrafo no README / Sobre.

    6.4 Segurança do conteúdo
    Não colar chaves, .env, journalctl com hostname real,
    e-mails de terceiros. O artigo de variáveis já ensina;
    o repo precisa seguir o próprio conselho.

    6.5 go 1.27.0 no go.mod
    Conferir se CI e máquina local realmente usam isso.
    Pode ser typo de 1.22/1.23/1.24. hugo version e go version
    devem bater com o README (hoje: Hugo v0.165.0+extended).

    6.6 public/ local é um mentiroso
    O diretório public/ mistura o build atual com URLs antigas
    (slug pelo título, typo criptgrafia, logs com acento).
    Nunca inspecionar SEO/rotas olhando public/ sem um
    hugo --cleanDestinationDir antes. Melhor nem versionar
    (já está no gitignore).
